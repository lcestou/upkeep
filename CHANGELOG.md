# Changelog

## Unreleased

- A run can now be stopped at once. After Stop after this one, the footer offers Stop now: the app being installed goes back to how it was and the apps behind it stay ready. Downloads, builds and a self-updating tool's own update command are cut; a step that runs as root (`dpkg -i`, `rpm -U`, `sudo make install`) or an undo is waited out first, and the row says what it waits for. A tool with no `restore` command is cut too, and its row says what version it reports afterwards. History shows the app as Stopped by you, and a run that ends early still records the apps it finished.
- A row whose step has printed nothing for two minutes says so, with the time left before the step's own limit ends it ("No output for 3 min. It stops on its own in 7 min."), and offers Stop now.
- In `upkeep install`, the first Ctrl-C (or SIGTERM, or closing the terminal) is Stop now, and a second one ends the step in progress and quits (a root step keeps running, and Upkeep says so). Before, Ctrl-C killed Upkeep straight away and reached a `sudo dpkg` in progress directly. Every process Upkeep starts now runs in a process group of its own.
- The Claude Code plugins row now says when an update is waiting. A check refreshes the plugin marketplaces, as Claude Code does at start, and compares each installed plugin's version with the one its marketplace now holds (for a plugin with no version, new commits in its own folder of the marketplace). The row turns to Update and names the plugins, so it shows in the count and the tray like any other update. A plugin whose marketplace entry points to another repo and names no version is still only updated by Run now or an automatic run.
- Settings has "Wait before offering a new release": Off (the default), 1 day, 3 days or 7 days, counted from the moment the release came out. A younger release sits under Held back and says when it will be offered ("Offered from Nov 27", or "Offered at 20:00" when that is later today), and turns Ready on its own at that moment, without a check. Automatic installs and the tray's Update all wait for it too. A pre-release, with its switch on, waits like any release, and a version you pick from Other versions never waits. The app's pane has "Install now anyway" to take it at once, and Retry after a failed one takes it again; `upkeep install <app>` naming the app skips the wait as well, while `--all` and `--auto` keep it. A release with no date (a `links`, `json` or command source) is offered as before, and so is an app you update by hand. Upkeep's own update does not wait. When the wait runs out the ready notice goes out without a check; an app set to install automatically installs at the next check. An import that shortens the wait asks first.
- Settings has a "GitHub token" field. A token pasted there raises GitHub's limit from 60 to 5,000 requests an hour and reaches private repos, without the gh CLI. GitHub is asked about it once when it is saved (for at most 10 seconds), and a token it refuses is not kept. It is used before gh's own sign-in; when GitHub refuses it later (it expired or was revoked), that check uses gh's sign-in and Settings says so. It is kept in its own file that only you can read (mode 0600), never written to the settings, an export or the log, and shown only by its last four characters. Remove forgets it.
- An app installed from GitHub, GitLab or Codeberg releases can follow pre-releases: switch on Follow pre-releases in its pane, or set `prerelease = true` in its table. Versions such as 2.0.0-rc.1 and 0.7.2-Beta now count as older than their release everywhere.
- Other versions in the same pane lists, when you ask, the newest releases that have a file for this machine, and installs the one you pick with a restore point, verify and rollback as usual. Going back to an older one skips the latest, as a restore point does, so the next newer release is still offered.
- While Upkeep installs updates, the computer does not go to sleep on an idle timer or from the menu: Upkeep holds a systemd-logind sleep lock from the start of the run to its end, and lets go when the run ends, is stopped or Upkeep quits. Shutdown is never held, and closing the lid still suspends under logind's defaults. This is on for everyone, since it only prevents a half-done update. A system without `systemd-inhibit` installs as before, and the run log says so once.
- A new setting, off by default: "Wait for an unmetered connection and mains power for automatic app updates". When it is on, the apps marked automatic do not install at login, and `upkeep install --auto` installs nothing, while NetworkManager says the connection is metered or UPower says the computer runs on battery. The login notice names them as ready and says what they wait for, and each scheduled check tries them again until they install. Checks still run, pressing Install always installs, and Upkeep's own automatic update is not held. Without NetworkManager or UPower the connection counts as unmetered and the power as mains.
- When Upkeep starts at login before the network is up, it checks again after 30 seconds, 2 minutes and 5 minutes. Meanwhile the rows keep what the last check found, instead of a network failure on every row, and the ready notice waits for a check that got through. Only a check that still finds no network after the last wait shows the failures.
- An AppImage's pane has a "Show in the app menu" switch, off by default. On, Upkeep writes a menu entry and icon taken from the AppImage itself, writes them again after each update, and deletes exactly those files when the switch goes off, the app leaves the list or Upkeep is uninstalled. When AppImageLauncher, Gear Lever or the app already made an entry for the same file, the row says so and adds no second one. An AppImage whose own entry asks to stay out of the menu gets none, and the pane says why.
- A release download with no GitHub digest is now held to the release's own checksum file when it has one (`SHA256SUMS`, `checksums.txt`, `<file>.sha256`, or electron-builder's `latest-linux.yml`), on GitHub (private repos included, with your sign-in), GitLab and Codeberg alike. A file that does not match fails like a digest mismatch, nothing is changed, and the row says you can skip that version. A file the checksum file vouches for no longer needs to be at least 1 MiB.
- After an update, the row's pane says how its download was checked: against the forge's SHA-256, against the release's checksum file, by size only, or not at all. History shows the same as a short line under each update, and the log and `upkeep history` say it too.
- When the file behind a release's tag changes after Upkeep first saw it, the row is held with the reason instead of offered. Release the hold to install it anyway, in the window or with the new `upkeep hold <app> off`; `upkeep check` prints the reason. GitHub releases marked immutable are never held this way.
- A download redirected from https to plain http is refused.
- An app's table can name its settings with `keep_with_restore = ["~/.config/<app>"]`. They are copied into each restore point before an update and put back with the old version, so an app that rewrote its config on first start of the new version can still read it after a restore. A restore asks you to close the app first while it runs. The settings a restore replaces are kept in `~/.local/share/upkeep/config-aside/<app>/` (the last three), and a point that holds settings says "with settings" in the row's details. Paths over 200 MB, links and mount points are left out with a log line; Upkeep's own folders, keys, menu and login entries are refused.
- Import no longer runs commands from a file you were handed without showing them first. When the imported list has apps that run commands on this computer (a command app's check and update, a source build's steps and the files it writes, a restart or relaunch, an install as root), Settings, Import lists each one with where its code comes from and its exact commands, and waits for Import or Cancel. A file that turns on a setting or extra that is off here, such as Upkeep's own automatic update or the System group, asks the same way; `upkeep import` prints them and needs `--yes`. Every app that is new to this computer or whose table differs from the one here comes in with automatic installs off, even when the file had them on, and Import says which. An app that matches keeps this computer's own choice, so no import turns an automatic install on. A list whose apps only install their release files, without root, imports in one step, as before.

## 0.1.8, 2026-11-21

- Add app follows an AppImage's own update information more closely. The publisher's file pattern from `gh-releases-zsync` becomes the table's `asset` when it picks one file. A `zsync|` address into a GitHub, GitLab or Codeberg release is read as that release, and a `zsync|` address on any other host is followed through the new `latest = "zsync:<address>"` source, which reads the latest file's name, address and size from the `.zsync` header. Thanks to @probonopd, whose question on the awesome-appimage listing started it.
- With "Restore points to keep" above 1, older restore points take less disk: every point but the newest is packed with zstd after an update, which halves a source build's saved trees (a 676 MB Strata point packs to about 300 MB). The newest point stays as it was, so a rollback after a failed start is as quick as before. AppImages and packages are already compressed and stay as they are.
- While one app installs, the apps behind it whose update is one release file (an AppImage, archive, plain file, `.deb` or `.rpm`) download their files, two at a time, so a long source build no longer holds their downloads back. A row whose file is in says "Downloaded, waits its turn", and its download shows full when its turn comes. Installs still run one at a time and in order. Stop cancels the early downloads and deletes their files.
- The window's close button no longer opens red when you bring Upkeep back from the tray. Closing hid the window with the pointer on the button, and the button kept its hover colour until the mouse moved. Minimize did the same.
- When a source build fails its check, the row says the reason the check printed, not the check's whole script. The Strata example and the source-build docs show how to start a service through a script that finds the files, so an upstream that moves its folders does not break the unit.
- A service that crashes right after an update (systemd keeps restarting it, or it stops) is rolled back within seconds, instead of after its whole wait (five minutes for Strata). The rollback stops it first, so systemd cannot restart it while the old files go back.
- A checkout updated with `move = "reset"` (ComfyUI's) no longer refuses with "has commits that are not on GitHub" when it sits on the previous release tag and its branch was not fetched since. HEAD inside the new release tag now counts as on GitHub; real local commits still refuse.
- Claude Code reads its newest version from the file `claude update` itself reads, so its update no longer fails during the hours a release is on npm but not yet on Claude's download server. A command table's `latest` can take `text:<https URL>` for a tool like that. Add app's scan still counts an npm-installed `@anthropic-ai/claude-code` as the Claude Code you already have: a scoped npm package is matched by a table named as the package without its scope.
- A `config` file pattern that matches no file now fails the update before anything is stopped, instead of writing nothing. A `hold` path that is not there is skipped.
- The Strata example follows Strata 0.2.16, which moved its files into `terminal/`. It checks the build with Strata's own `strata --version` and `strata doctor`, and checks that the files the systemd unit starts from still exist before it stops Strata.

## 0.1.6, 2026-11-17

- One command installs Upkeep: `curl -fsSL https://raw.githubusercontent.com/lcestou/upkeep/main/install.sh | sh` downloads the latest release's installer for the machine and runs it.
- On a 1x screen the tray icon is drawn from its 22 px masters, crisp, instead of the 2x picture scaled down. A 2x screen keeps the 2x picture.

Arch's pacman rows stay read-only, since Arch supports no partial upgrade.
- Upkeep starts on Fedora Workstation, Silverblue and Bazzite, which ship no tray library: Upkeep now carries its own.
- On an image-based system (Silverblue, Bazzite), whose system files cannot change outside an image update, Add app offers an app's AppImage or archive instead of its `.deb` or `.rpm`, and the System group lists Flatpak only instead of system packages it could not install.
- Add app no longer gives up on a catalogue app whose tested table installs a `.deb` or `.rpm` this machine cannot take: it offers another file of the same release that this machine can install, such as its AppImage.
- On Bazzite's and SteamOS's dark Vapor theme the tray icon is drawn light. Upkeep now reads the panel's colour, not only the theme's name.

## 0.1.0, 2026-11-16

First version.

- The Log follows new lines from the moment it opens, a scroll up to read pauses it, and a Pause / Follow new lines button switches it. A long build that prints hundreds of lines a second (a CUDA compile) no longer freezes the window: the log redraws only the lines that came and went, instead of every line it holds.
- Apps whose Linux build is a `.tar.xz`, `.tar.bz2` or `.tar.zst` archive (fish, kitty and many command-line tools) can be added and updated like `.tar.gz` ones. On a system without the program such an archive needs (Ubuntu's minimal images have no `xz`), or without `unzip` for a `.zip`, Upkeep names the program to install instead of saying the archive holds nothing. Source tarballs and Arch Linux packages in a release are no longer offered as builds.
- An app that opens its window when asked for its version, or never names one (many Tauri apps, a binary built without its version stamped in), can be kept up to date: its table says `probe = false`, and Upkeep reads the version it installed instead of starting the program. A copy installed some other way is offered the latest, since Upkeep cannot tell which version it is.
- An app shipped as a whole folder (a program with its `lib/` and data beside it, such as kitty) can be installed from its archive: the table's `folder` names where it unpacks, its programs are linked into `~/.local/bin`, an update swaps the folder in by rename, and a restore point keeps the old folder whole. Upkeep only ever replaces a folder it made for that app, and a table whose folder is home itself or a folder like `~/.local` is refused.
- An archive whose program carries the version in its file name (`ipatool-2.1.4-linux-amd64`) installs it under its plain name: the table's `bins` entry takes a `*` for the version.
- An AppImage's version is read from its metainfo whatever order the `<release>` element's attributes come in; one that wrote `date` before `version` was read at an older release.
- Add app refuses an app that would replace a script or a different tool of the same name at its install path (a Python `httpx` where the catalogue's is ProjectDiscovery's), instead of reading the script's version and offering to overwrite it.
- Add app no longer offers a macOS build whose name says only `mac` (Caddy's `caddy_2.11.9_mac_amd64.tar.gz`); it was taken as a Linux one and its install failed.
- A release file that spells the architecture `x86.64` (DB Browser for SQLite does) is taken as the x86_64 build; it was dropped as a 32-bit one.
- The catalogue has about 3,100 more apps: command-line tools and AppImages that ship their Linux builds on GitHub, with at least 100 stars and a release in the last two years, taken from the lists aqua's registry, mise's registry, AppImageHub and AM keep. Each table was written by Upkeep's own Add app logic from the app's latest release and checked to pick exactly one file of it, and a sample of them was installed for real. About two in three read the installed version the usual way, found by running each program once in a test machine (`--version`, `version`, `-V` or `-v`) or reading the version file inside each AppImage; the rest remember the version Upkeep installed rather than starting the program. An app that needs the files around it installs as a whole folder.
- The catalogue Add app looks in first has 83 more apps: Obsidian, LocalSend, Heroic Games Launcher, Joplin, Logseq, Vesktop, Bruno, Beekeeper Studio, yt-dlp, fastfetch, Tabby, MarkText, Motrix, dive, Spotube, SiYuan, Sniffnet, ShellCheck, AppFlowy, Lapce, Micro, gitleaks, Cool Retro Term, superfile, gitui, vhs, fx, hurl, asciinema, navi, ast-grep, gping, Espanso, Zettlr, DB Browser for SQLite, Recordly, Pear Desktop, Google Workspace CLI, Chat2DB, d2, asdf, Super Productivity, Notable, witr, Nuclear, Arnis, Harper, WTF, PakePlus, Skaffold, electerm, DevPod, ImageGlass, Notesnook, Sampler, Microsoft Edit, VNote, Zeal, gh-dash, Escrcpy, genact, gitoxide, fish, ipatool, Jan, DBX, Yaak, NoteGen, Trilium Notes, Readest, gron, kitty, Spicetify, AB Download Manager, Carbonyl, onefetch, bandwhich, slides, bore, nvtop, Listen 1, RapidRAW and KDiskMark. Each was installed for real and read back at its release's version, and an app whose version can only be read by opening its window reads it from the files inside the AppImage instead.
- Add app and Scan this computer say when something else already keeps an app up to date: a Flatpak or Snap of it, an apt repository for a package app, or a table in the list on the same project or install path. Adding is still allowed, for two versions side by side; a scanned app with such a note starts unticked. Scan also finds catalogue apps installed from a .deb or .rpm.
- An app added from a repo with a generic name, such as `gitlab.com/gitlab-org/cli`, is named after the program it ships (glab), not after the group, when the group's name does not contain it.
- With "Install system updates from Upkeep" on, Ubuntu, Debian and other systems with plain apt can install their package updates from the System group: the ticked packages go through `apt-get install --only-upgrade`, keeping config files you edited, after a dry run that refuses anything touching a kernel or NVIDIA package or removing a package. Before, only Linux Mint's Update Manager packages could.
- When GitHub's hourly request limit is used up, a bar under the header says when checks resume and, without a GitHub sign-in, that `gh auth login` in a terminal raises the limit to 5,000 an hour. Dismissing it hides it until the hour starts over.
- Adding Cursor, or any catalogue app that finds its version through its own update address or a download page rather than a repo, or a source build such as tmux, when it is not installed yet lands it in Ready to install. It was added to the list and then skipped by every check, so it never showed up. A tool that updates itself and is not installed yet now says on its card that it shows up once it is.
- **Uninstall Upkeep** at the end of Settings removes Upkeep with its menu entry, login entry, `upkeep` command and the copies its own updates keep, and on request its settings, app list, history and restore points. The installer's own `uninstall --quiet` left the menu and login entries behind, so the menu kept a dead item and every login tried to start it.
- The login and menu entries hold no escaped quotes when Upkeep is installed in a plain folder (the usual case), so `dex`, which i3 and other minimal sessions use to run login entries, starts Upkeep at login too.
- Scan this computer takes a program it finds where a catalogue app installs (fd, jq, uv, Helix and the rest) as that catalogue app, ticked and with its tested table, instead of guessing its repo through a GitHub search. A guessed table could pick the wrong file: jq's took a source zip and its install failed. The other programs a catalogue app's archive brings (uvx beside uv) are no longer offered as unknown apps.
- A pipx tool installed with extras or a version range (`pipx install "black[d]>=24"`) is found by the scan and by Add app; it was passed over as if it came from a URL. One pinned to an exact version stays with pipx, since an update would overwrite the pin.
- An AppImage that cannot start because the system has no libfuse2 (Ubuntu 24.04 and later ship without it) shows as needing a look instead of reading the "2" in libfuse.so.2 as its version. Any app that will not start now says the line it failed on.
- In the System group, a Flatpak app whose update keeps its version reads as a newer build, not as its branch ("stable"), and the rows Upkeep can install no longer say "Install it with apt."
- Cleanup no longer shows "0 B" beside packages apt removed, whose size apt does not report.
- `upkeep check` prints a held or skipped app as HELD (with the skipped version) instead of UPDATE, since `install --all` passes it by, and `upkeep history` gives a Cleanup entry's freed bytes instead of "? to ?".
- An app whose source lists no file size (Cursor, GitLab releases, `links:` pages) shows the size its download server states, in its row and while it downloads ("Downloading 120.0 of 328.1 MB"), and no longer shows 0 B. Upkeep asks the server only while an update is waiting; when the server states no size the cell stays empty and the selection total reads "at least".
- An `upkeep` command for the terminal and scripts, behind "Add the upkeep command" in Settings (off by default). It goes in `~/.local/bin`, runs the installed Upkeep's command line, keeps working across Upkeep's own updates, and leaves alone any `upkeep` file Upkeep did not write.
- Upkeep updates itself. A newer version shows as a row above the list; Update Upkeep downloads it, checks it and starts it once as a test beside the running one, and only then offers Restart now. The version being replaced is kept until the new one has started, and the menu and login entries put it back if the new one will not start. Settings has a switch for doing all of it unattended while Upkeep sits in the tray, off by default. An install made before this is replaced once with the installer.
- Settings, under About, has What's new, Report a bug and Upkeep on GitHub. A bug report opens a new issue with the version, the distribution and the desktop already filled in.
- A command-line tool that was running while it updated (uv inside a long-running uvx, say) no longer asks to be restarted: the row reads updated, with a note that the running copy keeps the old version until it exits. Apps with a window, packages and services still ask.
- Upkeep picks release files for arm64 (aarch64) machines as well as x86_64: it reads the machine's architecture, Add app offers only that machine's builds, and a table can name its arm64 file with `asset_aarch64`, which 37 catalogue apps now do. A catalogue app with no arm64 build is not offered on arm64, and an app moved from a machine of the other architecture says its table names no file for this one.
- A Cleanup tab, behind "Show Cleanup" in Settings (off by default), measures thumbnails, the Trash, Upkeep's leftover copies, restore points, apt's package cache, old NVIDIA Flatpak runtimes, packages nothing needs and, behind a second switch, the uv, bun, npm and pip caches, and deletes only what you tick after a review sheet that names the total and every command. It does not run while an interrupted update waits to be put back, and History shows an item it left alone as skipped.
- System updates can be installed from Upkeep behind a second switch, "Install system updates from Upkeep" (off by default): tick Update Manager's packages, Flatpak apps and runtimes, Snaps or Cinnamon spices, read the exact commands, and confirm. Kernels and the NVIDIA driver stay with Update Manager, and nothing runs when sudo would ask for a password, another installer holds the package lock, or a trial run would touch a kernel or driver.
- Apps can come from GitLab (gitlab.com or self-hosted), Codeberg and other Gitea or Forgejo hosts, as well as GitHub: a table's `repo` takes `gitlab.com/group/name` or `codeberg.org/owner/name`, and Add app reads links to them. An app whose project publishes no releases can follow a plain download page with `latest = "links:<page>"`.
- Scan this computer also finds the tools uv, pipx, npm and cargo installed and offers each as an app that updates through that manager; typing a tool's name in Add app finds it too. A tool from crates.io can have its latest version checked.
- Add app's line on how it worked out each suggestion shows in the chosen language; it is several sentences, and only a single one was translated before.
- Dropping a file on the window opens Add app with it. In the real window the drop did nothing, because the desktop's web view passes a dropped file's address only as link text.
- A catalogue app that is not installed yet lands in Ready to install when added, and Add app opens the release file its table names. An archive whose top folder shares the program's name (btop) installs, and a version line that starts with a commit hash (lazygit) reads the real version.
- The catalogue Add app looks in first has 25 more apps: ripgrep, lazygit, bottom, btop, eza, dust, duf, delta, hyperfine, pastel, GitHub CLI, glow, lazydocker, k9s, Zellij, Atuin, croc, just, xh, Difftastic, jq, yq, chezmoi, Neovim and Helix.
- The System group also lists pending updates of Cinnamon's applets, desklets, extensions and themes (the spices Update Manager shows), and of Snaps where snapd is installed.
- The window's groups (Ready to install, Fresh and the rest) list their apps alphabetically by name, not in the order they were added. The group for a run in progress still lists apps in the order they install.
- Apps that ship an `.rpm` on GitHub install, update and roll back through `rpm`, as `.deb` apps do through `dpkg`. Add app offers an `.rpm` only on a system without `dpkg`.
- Add app drafts a source build when nothing in a project's release runs on this computer. It reads the project's build file (Cargo, Go, Meson, CMake, autotools or a Makefile), shows every step as a guess to read before adding, and says when the build tool is missing. A `.deb` is no longer offered on a system without `dpkg`.
- What the engine reports in the window (a row's problem, why an install or restore failed, what Add app found, why an import was refused) now shows in the language picked, not only the window's own labels.
- Settings has Export and Import beside Open apps.toml, to carry the settings and app list to another computer as one file. The Language choice opens a list drawn inside the window, which no longer runs past its edge with scroll arrows and empty space.
- With nothing ready, the tray icon's plant is centred instead of leaving an empty space where the count badge goes.
- The command line can now do everything the window does: `list`, `add`, `remove`, and `export` and `import` of the settings and app list as one file to carry to another machine. Every command answers in JSON with `--json`, so a script or an agent can manage Upkeep without editing files.
- The window, the tray and the notifications come in ten languages: English, Chinese (Simplified), Spanish, Portuguese (Brazil), German, French, Italian, Polish, Russian and Japanese. Upkeep follows the desktop's language, or the one picked under **Language** in Settings, and switches at once. Counts use each language's own plural forms, and dates its own order.
- One window lists every app with its installed and latest version, its size and its restore point. Tick what you want and press Install once. Nothing asks a question after that.
- Each app shows its own progress through download, back up, install and verify.
- During a run, ticking a Ready app adds it to the end of the run, as a download manager would. The Installing group lists apps in the order they run, and an app's pane keeps its log on the newest line in a box of its own, so the pane no longer shifts as lines arrive.
- Deleting an old build or restore point no longer freezes the window: it is moved aside at once and deleted in the background. Checking whether an app is running no longer reads the memory of a process stuck on a closing AppImage, which could stall the window for minutes.
- A new version that will not start is replaced by the copy taken before it. .deb apps now keep the installed version's package as a restore point, and self-updating tools keep one when their table says how to install a given version (wrangler and claude-code-telegram in the catalogue do).
- Downloads are checked against the size and SHA-256 that GitHub lists.
- A running app is not closed. Its file is replaced and the row says "Restart to apply". An app whose table says how (a service's `systemctl restart`, or a desktop app Upkeep may close and reopen) can be restarted from its pane or from the "Restart to finish" group. Zen Browser and RustDesk in the catalogue can.
- An app built from source shows, in its pane, the commits it is behind by, newest first, and its row shows a Build stage while it builds.
- llama.cpp, Strata, ComfyUI, whisper.cpp, dsh and claude-code-telegram are updated by Upkeep itself, with restore points. Each builds while the running copy keeps serving, is swapped in only once the build passes, and is restarted and tested; anything that fails after the stop puts the old version back.
- `recover` from the command line finishes or undoes an update that was interrupted.
- Claude Code's plugins are one row that updates every installed plugin with `claude plugin update`, each in its own scope and project folder, and names the ones that failed. It never accepts a marketplace's command on the person's behalf. `versionless` now loads only on this row; anywhere else it is refused with the reason, since such a row would fail every run.
- Add an app by typing its name, pasting its GitHub repo, choosing or dropping a file, or scanning the computer. Remove one from its pane.
- A catalogue of 48 tested apps (AppImages, release binaries, .deb files, tools that update themselves, two built from source): typing one's name adds its known-good table.
- An AppImage can come from a vendor's own update API instead of GitHub (`latest = "json:<url>"`, an answer with a version and a download), which is how Cursor ships; it is in the catalogue. A download whose size nobody listed must be at least 1 MiB, and the version can be read from a `.json` inside the image.
- Restart now closes a desktop app by its top process only, so an Electron app such as Cursor shuts down cleanly instead of its windows dying one by one.
- A new list starts empty and says so, with Add app right there.
- Filter the list by name.
- A table whose `latest` names a source Upkeep cannot read (anything but `npm:`, `pypi:`, `github:`, `npm-tags:` or `json:`) is refused when the list loads, with the reason, instead of failing at every check.
- Skip one version of an app, hold an app, or mark it to install without asking.
- A tray icon shows how many updates are ready. One notification per new set of updates.
- Upkeep checks on its own while it runs, in the window or the tray: every 6 hours by default, once a day, or only when you ask (Settings, Check for updates). A machine that slept through the time checks once when it wakes, and a clock that jumps never stops the schedule.
- "Start at login" in Settings opens Upkeep in the tray when you log in and checks for updates. Off until you turn it on.
- History of every install, and a log per run.
- The window draws its own title bar inside its header, with the window buttons on the side your desktop puts them. Settings can move them, square the corners, or hand the frame back to the desktop.
- The list opens with what the last check found and refreshes in place. On the first machine 28 of 32 apps report in under two seconds.
- "Restart to apply" stays on a row until the old copy of the app is no longer running.
- `check`, `install`, `restore` and `history` from the command line, through `bun run cli`.
- The window no longer comes up blank on openSUSE. The framework's launcher pointed `ICU_DATA` at a folder with no ICU data, which openSUSE's WebKit cannot start a page without; Upkeep clears it when the folder holds none.
- An optional, read-only System group lists the system's own pending updates without installing any: Flatpak apps and runtimes anywhere, and packages from Linux Mint's Update Manager, or else from apt, dnf, pacman or zypper. On Arch, a `checkupdates` that cannot run (it needs fakeroot) falls back to `pacman -Qu` instead of leaving the list empty.
