# Changelog

## 0.1.0, unreleased

First version.

- The catalogue Add app looks in first has 10 more apps: Obsidian, LocalSend, Heroic Games Launcher, Joplin, Logseq, Vesktop, Bruno, Beekeeper Studio, yt-dlp and fastfetch. The AppImages' versions are read from the files inside them, so checking never opens their windows.
- Add app and Scan this computer say when something else already keeps an app up to date: a Flatpak or Snap of it, an apt repository for a package app, or a table in the list on the same project or install path. Adding is still allowed, for two versions side by side; a scanned app with such a note starts unticked. Scan also finds catalogue apps installed from a .deb or .rpm.
- An app added from a repo with a generic name, such as `gitlab.com/gitlab-org/cli`, is named after the program it ships (glab), not after the group, when the group's name does not contain it.
- With "Install system updates from Upkeep" on, Ubuntu, Debian and other systems with plain apt can install their package updates from the System group: the ticked packages go through `apt-get install --only-upgrade`, keeping config files you edited, after a dry run that refuses anything touching a kernel or NVIDIA package or removing a package. Before, only Linux Mint's Update Manager packages could.
- When GitHub's hourly request limit is used up, a bar under the header says when checks resume and, without a GitHub sign-in, that `gh auth login` in a terminal raises the limit to 5,000 an hour. Dismissing it hides it until the hour starts over.
- Adding Cursor, or any catalogue app that finds its version through its own update address or a download page rather than a repo, or a source build such as tmux, when it is not installed yet lands it in Ready to install. It was added to the list and then skipped by every check, so it never showed up. A tool that updates itself and is not installed yet now says on its card that it shows up once it is.
- **Uninstall Upkeep** at the end of Settings removes Upkeep with its menu entry, login entry, `upkeep` command and the copies its own updates keep, and on request its settings, app list, history and restore points. The installer's own `uninstall --quiet` left the menu and login entries behind, so the menu kept a dead item and every login tried to start it.
- The login and menu entries hold no escaped quotes when Upkeep is installed in a plain folder (the usual case), so `dex`, which i3 and other minimal sessions use to run login entries, starts Upkeep at login too.
- Scan this computer takes a program it finds where a catalogue app installs (fd, jq, uv, Helix and the rest) as that catalogue app, ticked and with its tested table, instead of guessing its repo through a GitHub search. A guessed table could pick the wrong file: jq's took a source zip and its install failed. The other programs a catalogue app's archive brings (uvx beside uv) are no longer offered as unknown apps.
- A pipx tool installed with extras or a version range (`pipx install "black[d]>=24"`) is found by the scan and by Add app; it was passed over as if it came from a URL. One pinned to an exact version stays with pipx, since an update would overwrite the pin.
- An AppImage that cannot start because the system has no libfuse2 (Ubuntu 24.04 and later ship without it) shows as needing a look instead of reading the "2" in libfuse.so.2 as its version. Any app that will not start now says the line it failed on.
- In the System group, a Flatpak app whose update keeps its version reads as a newer build, not as its branch ("stable"), and the rows Upkeep can install no longer say "Install it with apt."
- Cleanup no longer shows "0 B" beside packages apt removed, whose size apt does not report.
- `upkeep check` prints a held or skipped app as HELD (with the skipped version) instead of UPDATE, since `install --all` passes it by, and `upkeep history` gives a Cleanup entry's freed bytes instead of "? to ?".
- An app whose source lists no file size (Cursor, GitLab releases, `links:` pages) shows the size its download server states, in its row and while it downloads ("Downloading 120.0 of 328.1 MB"), and no longer shows 0 B. Upkeep asks the server only while an update is waiting; when the server states no size the cell stays empty and the selection total reads "at least".
- An `upkeep` command for the terminal and scripts, behind "Add the upkeep command" in Settings (off by default). It goes in `~/.local/bin`, runs the installed Upkeep's command line, keeps working across Upkeep's own updates, and leaves alone any `upkeep` file Upkeep did not write.
- Upkeep updates itself. A newer version shows as a row above the list; Update Upkeep downloads it, checks it and starts it once as a test beside the running one, and only then offers Restart now. The version being replaced is kept until the new one has started, and the menu and login entries put it back if the new one will not start. Settings has a switch for doing all of it unattended while Upkeep sits in the tray, off by default. An install made before this is replaced once with the installer.
- Settings, under About, has What's new, Report a bug and Upkeep on GitHub. A bug report opens a new issue with the version, the distribution and the desktop already filled in.
- A command-line tool that was running while it updated (uv inside a long-running uvx, say) no longer asks to be restarted: the row reads updated, with a note that the running copy keeps the old version until it exits. Apps with a window, packages and services still ask.
- Upkeep picks release files for arm64 (aarch64) machines as well as x86_64: it reads the machine's architecture, Add app offers only that machine's builds, and a table can name its arm64 file with `asset_aarch64`, which 37 catalogue apps now do. A catalogue app with no arm64 build is not offered on arm64, and an app moved from a machine of the other architecture says its table names no file for this one.
- A Cleanup tab, behind "Show Cleanup" in Settings (off by default), measures thumbnails, the Trash, Upkeep's leftover copies, restore points, apt's package cache, old NVIDIA Flatpak runtimes, packages nothing needs and, behind a second switch, the uv, bun, npm and pip caches, and deletes only what you tick after a review sheet that names the total and every command. It does not run while an interrupted update waits to be put back, and History shows an item it left alone as skipped.
- System updates can be installed from Upkeep behind a second switch, "Install system updates from Upkeep" (off by default): tick Update Manager's packages, Flatpak apps and runtimes, Snaps or Cinnamon spices, read the exact commands, and confirm. Kernels and the NVIDIA driver stay with Update Manager, and nothing runs when sudo would ask for a password, another installer holds the package lock, or a trial run would touch a kernel or driver.
- Apps can come from GitLab (gitlab.com or self-hosted), Codeberg and other Gitea or Forgejo hosts, as well as GitHub: a table's `repo` takes `gitlab.com/group/name` or `codeberg.org/owner/name`, and Add app reads links to them. An app whose project publishes no releases can follow a plain download page with `latest = "links:<page>"`.
- Scan this computer also finds the tools uv, pipx, npm and cargo installed and offers each as an app that updates through that manager; typing a tool's name in Add app finds it too. A tool from crates.io can have its latest version checked.
- Add app's line on how it worked out each suggestion shows in the chosen language; it is several sentences, and only a single one was translated before.
- Dropping a file on the window opens Add app with it. In the real window the drop did nothing, because the desktop's web view passes a dropped file's address only as link text.
- A catalogue app that is not installed yet lands in Ready to install when added, and Add app opens the release file its table names. An archive whose top folder shares the program's name (btop) installs, and a version line that starts with a commit hash (lazygit) reads the real version.
- The catalogue Add app looks in first has 25 more apps: ripgrep, lazygit, bottom, btop, eza, dust, duf, delta, hyperfine, pastel, GitHub CLI, glow, lazydocker, k9s, Zellij, Atuin, croc, just, xh, Difftastic, jq, yq, chezmoi, Neovim and Helix.
- The System group also lists pending updates of Cinnamon's applets, desklets, extensions and themes (the spices Update Manager shows), and of Snaps where snapd is installed.
- The window's groups (Ready to install, Fresh and the rest) list their apps alphabetically by name, not in the order they were added. The group for a run in progress still lists apps in the order they install.
- Apps that ship an `.rpm` on GitHub install, update and roll back through `rpm`, as `.deb` apps do through `dpkg`. Add app offers an `.rpm` only on a system without `dpkg`.
- Add app drafts a source build when nothing in a project's release runs on this computer. It reads the project's build file (Cargo, Go, Meson, CMake, autotools or a Makefile), shows every step as a guess to read before adding, and says when the build tool is missing. A `.deb` is no longer offered on a system without `dpkg`.
- What the engine reports in the window (a row's problem, why an install or restore failed, what Add app found, why an import was refused) now shows in the language picked, not only the window's own labels.
- Settings has Export and Import beside Open apps.toml, to carry the settings and app list to another computer as one file. The Language choice opens a list drawn inside the window, which no longer runs past its edge with scroll arrows and empty space.
- With nothing ready, the tray icon's plant is centred instead of leaving an empty space where the count badge goes.
- The command line can now do everything the window does: `list`, `add`, `remove`, and `export` and `import` of the settings and app list as one file to carry to another machine. Every command answers in JSON with `--json`, so a script or an agent can manage Upkeep without editing files.
- The window, the tray and the notifications come in ten languages: English, Chinese (Simplified), Spanish, Portuguese (Brazil), German, French, Italian, Polish, Russian and Japanese. Upkeep follows the desktop's language, or the one picked under **Language** in Settings, and switches at once. Counts use each language's own plural forms, and dates its own order.
- One window lists every app with its installed and latest version, its size and its restore point. Tick what you want and press Install once. Nothing asks a question after that.
- Each app shows its own progress through download, back up, install and verify.
- During a run, ticking a Ready app adds it to the end of the run, as a download manager would. The Installing group lists apps in the order they run, and an app's pane keeps its log on the newest line in a box of its own, so the pane no longer shifts as lines arrive.
- Deleting an old build or restore point no longer freezes the window: it is moved aside at once and deleted in the background. Checking whether an app is running no longer reads the memory of a process stuck on a closing AppImage, which could stall the window for minutes.
- A new version that will not start is replaced by the copy taken before it. .deb apps now keep the installed version's package as a restore point, and self-updating tools keep one when their table says how to install a given version (wrangler and claude-code-telegram in the catalogue do).
- Downloads are checked against the size and SHA-256 that GitHub lists.
- A running app is not closed. Its file is replaced and the row says "Restart to apply". An app whose table says how (a service's `systemctl restart`, or a desktop app Upkeep may close and reopen) can be restarted from its pane or from the "Restart to finish" group. Zen Browser and RustDesk in the catalogue can.
- An app built from source shows, in its pane, the commits it is behind by, newest first, and its row shows a Build stage while it builds.
- llama.cpp, Strata, ComfyUI, whisper.cpp, dsh and claude-code-telegram are updated by Upkeep itself, with restore points. Each builds while the running copy keeps serving, is swapped in only once the build passes, and is restarted and tested; anything that fails after the stop puts the old version back.
- `recover` from the command line finishes or undoes an update that was interrupted.
- Claude Code's plugins are one row that updates every installed plugin with `claude plugin update`, each in its own scope and project folder, and names the ones that failed. It never accepts a marketplace's command on the person's behalf. `versionless` now loads only on this row; anywhere else it is refused with the reason, since such a row would fail every run.
- Add an app by typing its name, pasting its GitHub repo, choosing or dropping a file, or scanning the computer. Remove one from its pane.
- A catalogue of 48 tested apps (AppImages, release binaries, .deb files, tools that update themselves, two built from source): typing one's name adds its known-good table.
- An AppImage can come from a vendor's own update API instead of GitHub (`latest = "json:<url>"`, an answer with a version and a download), which is how Cursor ships; it is in the catalogue. A download whose size nobody listed must be at least 1 MiB, and the version can be read from a `.json` inside the image.
- Restart now closes a desktop app by its top process only, so an Electron app such as Cursor shuts down cleanly instead of its windows dying one by one.
- A new list starts empty and says so, with Add app right there.
- Filter the list by name.
- A table whose `latest` names a source Upkeep cannot read (anything but `npm:`, `pypi:`, `github:`, `npm-tags:` or `json:`) is refused when the list loads, with the reason, instead of failing at every check.
- Skip one version of an app, hold an app, or mark it to install without asking.
- A tray icon shows how many updates are ready. One notification per new set of updates.
- Upkeep checks on its own while it runs, in the window or the tray: every 6 hours by default, once a day, or only when you ask (Settings, Check for updates). A machine that slept through the time checks once when it wakes, and a clock that jumps never stops the schedule.
- "Start at login" in Settings opens Upkeep in the tray when you log in and checks for updates. Off until you turn it on.
- History of every install, and a log per run.
- The window draws its own title bar inside its header, with the window buttons on the side your desktop puts them. Settings can move them, square the corners, or hand the frame back to the desktop.
- The list opens with what the last check found and refreshes in place. On the first machine 28 of 32 apps report in under two seconds.
- "Restart to apply" stays on a row until the old copy of the app is no longer running.
- `check`, `install`, `restore` and `history` from the command line, through `bun run cli`.
- The window no longer comes up blank on openSUSE. The framework's launcher pointed `ICU_DATA` at a folder with no ICU data, which openSUSE's WebKit cannot start a page without; Upkeep clears it when the folder holds none.
- An optional, read-only System group lists the system's own pending updates without installing any: Flatpak apps and runtimes anywhere, and packages from Linux Mint's Update Manager, or else from apt, dnf, pacman or zypper. On Arch, a `checkupdates` that cannot run (it needs fakeroot) falls back to `pacman -Qu` instead of leaving the list empty.
