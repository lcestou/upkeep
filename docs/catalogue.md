# The catalogue

`catalogue/` holds one file per app, `catalogue/<key>.toml`, each with the single `[apps.<key>]` table Add app writes when someone picks that app. To add an app, write its table the way it works on your machine, name the file after its key, and open a pull request; a unit test loads every file, so a broken one fails the gate. A table carries `asset_aarch64` when the release has an arm64 build of the same kind, and a test holds each pattern, for either machine, to exactly one file of the release saved in `src/engine/fixtures/catalogue-assets.json`. Apps built from source, which name a person's own folders and services, stay out of the catalogue: `manifest/examples.toml` shows them instead. No catalogue table sets `auto`. [catalogue/README.md](../catalogue/README.md) says where the tables came from and thanks the projects whose lists helped.

A table may list versions nobody should get, with the reason: `bad_versions = ["2.4.1", "2.4.2"]` and `bad_reason = "crashes on start under Wayland (https://github.com/owner/name/issues/123)"`. A check never offers a listed version. It offers the newest release before it instead, or, when there is none newer than what is installed, leaves the row where it is, and the row's details give the reason either way. Other versions in the app's pane still lists it, for a person who wants it anyway. A command app's own updater only ever takes the latest, so a listed latest leaves it where it is. A table with `bad_versions` and no `bad_reason` is refused when it loads. Put a link to the issue in the reason: a wrong entry holds people on an old version, so each entry needs its evidence. Remove the entry once a fixed release is out, or leave it, since a newer release is offered anyway.
